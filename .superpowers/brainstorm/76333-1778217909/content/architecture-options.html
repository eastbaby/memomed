Memomed Enterprise Architecture Options

Choose the architecture story we want to carry into the design spec and interviews.

A

Recommended: Enterprise Harness + LangGraph Domain Workflows

Use a lightweight agent harness for routing, context assembly, policy, tools, memory, traces, and evals. Use LangGraph for medical-report RAG and medication/follow-up workflows where state control and HITL matter.

Pros

  • Best balance of interview depth and feasible implementation.
  • Lets you discuss platform concepts without overbuilding a platform.
  • Medical safety is explicit and auditable.

Cons

  • Requires disciplined boundaries so the harness does not become a vague god layer.
B

Deep Agents / Hermes-like Personal Agent First

Build an always-on personal assistant with persistent memory, skills, scheduled automations, subagents, and multi-channel reach, inspired by Hermes Agent and OpenClaw-style assistants.

Pros

  • Strong platform-framework story.
  • Shows awareness of modern autonomous agent systems.

Cons

  • Too open-ended for healthcare unless heavily constrained.
  • Risk of looking like copied platform buzzwords rather than a solved domain problem.
C

Workflow-only LangGraph Application

Keep everything inside one or several LangGraph graphs. Focus on report ingestion, RAG, medication reminders, and chat responses without a separate harness abstraction.

Pros

  • Easiest to implement quickly.
  • Very concrete and demo-friendly.

Cons

  • Weaker answer to enterprise platform and infra questions.
  • Routing, policies, evals, and memory may feel bolted on later.

My recommendation

Pick A. It lets Memomed be a serious healthcare assistant, not a general autonomous agent, while still giving you a strong platform-level interview narrative.
